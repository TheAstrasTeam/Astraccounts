# Astraccounts API

Base URL:

```text
[http://127.0.0.1:8080](http://127.0.0.1:8080)
```

All JSON requests must set:

```http
Content-Type: application/json
```

All JSON responses use UTF-8.

## API Overview

| Method | Path | Description | Success Status |
|---|---|---|---:|
| `GET` | `/api/health` | Health check | `200` |
| `POST` | `/api/register` | Register a user | `201` |
| `POST` | `/api/login` | Login and obtain token | `200` |
| `POST` | `/api/login/totp` | Login with TOTP code | `200` |
| `POST` | `/api/login/recovery_code` | Login with recovery code | `200` |
| `POST` | `/api/totp/sign` | Generate TOTP secret (unverified) | `200` |
| `POST` | `/api/totp/verify` | Verify TOTP code and activate | `200` |
| `POST` | `/api/totp/unsign` | Remove TOTP from a user | `200` |
| `POST` | `/api/profile/edit` | Edit user profile | `200` |
| `POST` | `/api/profile/view` | View user profile | `200` |

## General Behavior

### HTTP Status Codes

- `200`: Request succeeded
- `201`: Resource created successfully (used only by the register endpoint)
- `400`: Invalid parameters, authentication failed, or target user invalid
- `500`: Server failed to read or write data

### UID

UID is a positive integer generated by the server during registration, starting from `1`. User files are stored at:

```text
data/user/[UID]/user.json
```

### Token

A token is issued upon successful login. The current token format is:

```text
aat_<user-id>_<issued-at-unix-seconds>_<hmac-sha256>
```

For example:

```text
aat_ExampleUser_1788615478_f6e0205b57203f83614640ab7b0c07d3d927f1a38eb6a292a3bf2856fa2eeeba
```

Token features:

- Contains the user's `id`
- Contains issuance timestamp
- Does NOT contain username, email, password, or password hash
- Signed using HMAC-SHA256 with `TOKEN_SECRET`
- Expires after `TOKEN_VALID_SECS` seconds
- Can only be used for the corresponding user encoded within it

### Request

```http
GET /api/health
```

Does not require a request body, UID, or token.

### Successful Response

HTTP `200`:

```json
{
  "status": 200

```

## `POST /api/register`

Registers a new user.

### Request

```http
POST /api/register
Content-Type: application/json
```

```json
{
  "username": "Example",
  "id": "ExampleUser",
  "email": "user@example.com",
  "password": "Example123456*"
}
```

### Request Fields

| Field | Type | Required | Rules |
|---|---|---|---|
| `username` | string | Yes | Any Unicode characters allowed except `\r` or `\n`; cannot be empty |
| `id` | string | Yes | Uppercase/lowercase English letters, numbers, and `_` only |
| `email` | string | Yes | Must be a valid email address; case-insensitive and unique |
| `password` | string | Yes | English letters, numbers, `_`, and `!@#$%^&*` only |

`id` must not collide with existing users. Emails must not collide with existing users (case-insensitive comparison).

### Successful Response

HTTP `201`:

```json
{
  "status": 201,
  "UID": 1
}
```

During registration, the server automatically populates:

```json
"profile": {
  "username": "Example",
  "register": 1788665697
}
```

Where `register` is the registration timestamp in Unix seconds.

### Parameter Error Response

HTTP `400`:

```json
{
  "status": 400,
  "err": 2
}
```

`err` mapping:

| Value | Meaning |
|---:|---|
| `0` | Invalid request JSON format |
| `1` | Invalid username |
| `2` | Invalid ID or ID already in use |
| `3` | Invalid email or email already in use |
| `4` | Invalid password |

### Server Error

HTTP `500`:

```json
{
  "status": 500
}
```

## `POST /api/login`

Login using user ID or email.

### Request: Using ID

```json
{
  "query": "ExampleUser",
  "password": "Example123456*"
}
```

### Request: Using Email

```json
{
  "query": "user@example.com",
  "password": "Example123456*"
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `query` | string | Yes | User ID or Email |
| `password` | string | Yes | User password |

### Successful Response

HTTP `200`:

```json
{
  "status": 200,
  "token": "aat_ExampleUser_1788615478_f6e0205b57203f83614640ab7b0c07d3d927f1a38eb6a292a3bf2856fa2eeeba"
}
```

A new token is generated on every successful login.

### Login Failure

Returns HTTP `400` when the user does not exist, password is incorrect, JSON is invalid, or required fields are empty:

```json
{
  "status": 400
}
```

To prevent account enumeration, non-existent users and wrong passwords yield the exact same error response.

## `POST /api/totp/sign`

Generate a TOTP secret and return the `otpauth://` URI. This does **not** require a token; you must re-enter your ID/email and password. TOTP is **not yet active** after this call — you must call `/api/totp/verify` with a valid code to complete setup.

### Request

```http
POST /api/totp/sign
Content-Type: application/json
```

```json
{
  "query": "ExampleUser",
  "password": "Example123456*"
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `query` | string | Yes | User ID or email address |
| `password` | string | Yes | User password |

### Success Response

HTTP `200`:

```json
{
  "status": 200,
  "otpauth_url": "otpauth://totp/Astraccounts:ExampleUser?algorithm=SHA1&digits=6&issuer=Astraccounts&period=30&secret=JBSWY3DPEHPK3PXP"
}
```

The `otpauth_url` is a standard [otpauth URI](https://github.com/google/google-authenticator/wiki/Key-Uri-Format) that can be scanned as a QR code by authenticator apps (Google Authenticator, Authy, etc.).

You can call `/api/totp/sign` again to get a fresh secret (for example if the user lost the QR code) **as long as** you have not yet called `/api/totp/verify` successfully.

### TOTP Already Verified

HTTP `400`:

```json
{
  "status": 400,
  "err": 1
}
```

TOTP is already active. Call `/api/totp/unsign` first to remove it.

### Authentication Failure

HTTP `400`:

```json
{
  "status": 400
}
```

Returned when the user does not exist or the password is incorrect.

## `POST /api/totp/verify`

Verify a TOTP code to activate two-factor authentication. This does **not** require a token; you must re-enter your ID/email and password. On success, recovery codes are returned. On failure, the TOTP secret is removed and you must start over from `/api/totp/sign`.

### Request

```http
POST /api/totp/verify
Content-Type: application/json
```

```json
{
  "query": "ExampleUser",
  "password": "Example123456*",
  "code": "123456"
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `query` | string | Yes | User ID or email address |
| `password` | string | Yes | User password |
| `code` | string | Yes | 6-digit TOTP code from authenticator app |

### Success Response

HTTP `200`:

```json
{
  "status": 200,
  "recovery_codes": [
    "72OS-3ZWM-5BGR-TFLR",
    "GJ2W-R5CZ-IRGN-WDJS",
    "ODKC-JC3H-KNWF-OCOS",
    "IAZS-AQDT-W2LK-H3ZZ",
    "JMNIV-ZJYM-XP5M-DVSO",
    "XL7D-ULYK-6NHY-RR72",
    "OS3Z-WM5B-GR2T-FLRME",
    "POZG-J2WR-5CZI-RGNW",
    "DAJS-ODKC-JC3H-KNWF",
    "OCOS-IAZS-AQDT-W2LK"
  ]
}
```

10 recovery codes are generated. Each can only be used **once** to log in if the user loses access to their authenticator app. Store them securely — they cannot be viewed again after this response.

### Verification Failed

HTTP `400`:

```json
{
  "status": 400
}
```

The code was incorrect. The TOTP secret is **removed** entirely — you must call `/api/totp/sign` again to start over.

### Not Ready to Verify

HTTP `400`:

```json
{
  "status": 400
}
```

TOTP has not been set up via `/api/totp/sign`, or it has already been verified.

### Request

```http
POST /api/login/totp
Content-Type: application/json
```

```json
{
  "query": "ExampleUser",
  "code": "123456"
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `query` | string | Yes | User ID or email address |
| `code` | string | Yes | 6-digit TOTP code from authenticator app |

### Success Response

HTTP `200`:

```json
{
  "status": 200,
  "token": "aat_ExampleUser_1788615478_f6e0205b57203f83614640ab7b0c07d3d927f1a38eb6a292a3bf2856fa2eeeba"
}
```

### Login Failure

HTTP `400`:

```json
{
  "status": 400
}
```

Returned when the user does not exist, TOTP is not enabled, or the code is invalid.

| Field | Type | Required | Description |


## Profile Fields

Profiles are stored within the `profile` object of the user's `user.json`:

```json
{
  "profile": {
    "username": "Example",
    "register": 1788665697,
    "publicKey": "bruh",
    "publicBool": true,
    "publicNum": 114514,
    "superSecretKey": "imverysecretshouldbeprivate"
  }
}
```

### Custom Profile Fields

Custom fields must be defined in `.env` under `ALLOWED_PROFILE_KEY`:

```env
ALLOWED_PROFILE_KEY=publicKey:string,publicBool:bool,publicNum:number,superSecretKey:string:private
```

Format:

```text
name:type[:visibility]
```

Supported types:

- `string`
- `number`
- `bool`

Visibility options:

- `public` (or omitted): Viewable by anonymous requests
- `private`: Viewable only with a valid token from the target user

### Built-in Fields

The following fields do not need declaration in `.env`:

| Key | Type | On Registration | Editable |
|---|---|---|---|
| `username` | string | Populated by server from registration payload | Yes |
| `register` | number | Populated by server as Unix timestamp (seconds) | **No** |

Declaring `username` or `register` in `ALLOWED_PROFILE_KEY` will cause service initialization to fail.

## `POST /api/profile/edit`

Modifies profile fields for a specified UID. Requires a valid token belonging to the user specified by `UID`.

### Request

```http
POST /api/profile/edit
Content-Type: application/json
```

```json
{
  "UID": 123,
  "token": "[TOKEN]",
  "content": [
    {
      "key": "publicKey",
      "value": "bruh"
    },
    {
      "key": "publicNum",
      "value": 114514
    },
    {
      "key": "publicBool",
      "value": true
    }
  ]
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `UID` | number | Yes | UID of the user to edit |
| `token` | string | Yes | Valid token matching the UID |
| `content` | array | Yes | List of key/value pairs to write |
| `content[].key` | string | Yes | Must be an allowed profile key |
| `content[].value` | any | Yes | Must match the data type configured for the key |

`register` is a read-only field; attempts to edit it will be rejected even if the value type matches.

### Successful Response

HTTP `200`:

```json
{
  "status": 200
}
```

### Invalid Fields Response

HTTP `400`:

```json
{
  "status": 400,
  "invalid": [
    "unknownKey",
    "publicNum"
  ]
}
```

`invalid` array contains all rejected keys due to:

- Key not declared in configuration
- Key is a read-only built-in field
- Value type mismatch
- Keys that are not strings echo their raw JSON value

If any field in `content` is invalid, the entire update fails transactionally; no partial updates are applied.

### Authentication Failure

Returns HTTP `400` if UID does not exist, token is missing, token is invalid, or token belongs to a different user:

```json
{
  "status": 400
}
```

### Server Error

Returns HTTP `500` if the server fails to read or write the user file:

```json
{
  "status": 500
}
```

## `POST /api/profile/view`

Views a specified user's profile.

### Anonymous View

Request:

```json
{
  "UID": 123
}
```

Response includes public fields only:

```json
{
  "status": 200,
  "content": {
    "username": "Example",
    "register": 1788665697,
    "publicKey": "bruh",
    "publicBool": true
  }
}
```

### View Full Profile (Self)

Request:

```json
{
  "UID": 123,
  "token": "[TOKEN]"
}
```

If the token is valid and belongs to the user associated with `UID`, the response includes both public and private fields:

```json
{
  "status": 200,
  "content": {
    "username": "Example",
    "register": 1788665697,
    "publicKey": "bruh",
    "publicBool": true,
    "superSecretKey": "imverysecretshouldbeprivate"
  }
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `UID` | number | Yes | UID of the user to view |
| `token` | string | No | Valid token belonging to the target user; if omitted, returns public fields only |

Invalid tokens, tokens belonging to other users, and omitted tokens behave identically: they return public fields without throwing an error.

### User Not Found

HTTP `400`:

```json
{
  "status": 400
}
```

### Server Error

HTTP `500`:

```json
{
  "status": 500
}
```

## Example Workflow

### 1. Register

```bash
curl -s -X POST [http://127.0.0.1:8080/api/register](http://127.0.0.1:8080/api/register) \
  -H "Content-Type: application/json" \
  -d '{
    "username": "Example",
    "id": "ExampleUser",
    "email": "user@example.com",
    "password": "Example123456*"
  }'
```

### 2. Login

```bash
LOGIN_RESPONSE=$(curl -s -X POST [http://127.0.0.1:8080/api/login](http://127.0.0.1:8080/api/login) \
  -H "Content-Type: application/json" \
  -d '{
    "query": "ExampleUser",
    "password": "Example123456*"
  }')

TOKEN=$(echo "$LOGIN_RESPONSE" | jq -r '.token')
```

### 3. Modify Profile

```bash
curl -s -X POST [http://127.0.0.1:8080/api/profile/edit](http://127.0.0.1:8080/api/profile/edit) \
  -H "Content-Type: application/json" \
  -d "{
    \"UID\": 1,
    \"token\": \"$TOKEN\",
    \"content\": [
      { \"key\": \"publicKey\", \"value\": \"bruh\" },
      { \"key\": \"publicBool\", \"value\": true },
      { \"key\": \"publicNum\", \"value\": 114514 }
    ]
  }"
```

### 4. View Profile

```bash
curl -s -X POST [http://127.0.0.1:8080/api/profile/view](http://127.0.0.1:8080/api/profile/view) \
  -H "Content-Type: application/json" \
  -d '{ "UID": 1 }'
```
